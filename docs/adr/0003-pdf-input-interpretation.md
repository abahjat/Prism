# ADR 0003: Pure-Rust PDF Input Interpretation via `hayro`

- **Status:** Accepted
- **Date:** 2026-10-23
- **Milestone:** Phase 1 — M0 (Spikes and ADRs)

## Context

In Phase 0, PDFs were parsed with `lopdf` for text and metadata while visual rendering relied on embedding the raw PDF bytes in HTML and rendering them client-side with a bundled copy of `pdf.js`. That architecture could not support server-side rasterization (PNG/TIFF), unified search hit bounding boxes, PDF re-export, or redaction without running a browser.

Phase 1 requires a pure-Rust PDF interpreter (`hayro` / `hayro-interpret` / `hayro-syntax`) that interprets PDF pages directly into `prism-layout`'s `LayoutPage` model so that search, text selection, SVG viewing, PNG/TIFF rasterization, and PDF export all share one code path.

The key unknown identified for M0 was whether `hayro` can expose positioned glyphs, Unicode mappings, font data, vector paths, clips, and images into a custom device, or whether it only rasterizes pages to bitmaps.

## M0 Spike Findings

We inspected and executed `hayro 0.8.0`, `hayro-interpret 0.8.0`, and `hayro-syntax 0.8.0` (`Apache-2.0 OR MIT`, `#![forbid(unsafe_code)]`) against `test-files/testComment.pdf` and a `krilla`-generated PDF:

1. **Custom `Device<'a>` trait in `hayro-interpret 0.8.0`:**
   `hayro_interpret::interpret_page(page, &mut context, &mut device)` drives any implementation of `hayro_interpret::Device<'a>`, which receives:
   - `draw_glyph_run(&mut self, glyph_run: &GlyphRun<'_, 'a>, props: DrawProps<'a>, draw_mode: &DrawMode)`
   - `draw_path(&mut self, path: &BezPath, props: DrawProps<'a>, draw_mode: &DrawMode)`
   - `draw_rect(&mut self, rect: &Rect, props: DrawProps<'a>, draw_mode: &DrawMode)`
   - `draw_image(&mut self, image: Image<'a, '_>, props: ImageDrawProps<'a>)`
   - `push_clip_path(&mut self, clip_path: &ClipPath)` / `push_clip_rect(&mut self, rect: &Rect)` / `pop_clip(&mut self)`
   - `push_transparency_group(&mut self, opacity: f32, mask: Option<SoftMask<'a>>, blend_mode: BlendMode)` / `pop_transparency_group(&mut self)`
   - `begin_marked_content(&mut self, tag: &[u8], mcid: Option<i32>)` / `end_marked_content(&mut self)`

2. **Full Glyph, Outline, Font, and Unicode Access:**
   Each `PositionedGlyph<'a>` in `hayro_interpret::font::GlyphRun` provides its text-space `transform()` (`kurbo::Affine`) and dereferences to `Glyph<'a>`:
   - `Glyph::Outline(OutlineGlyph)` provides:
     - `glyph_id(&self) -> skrifa::GlyphId`
     - `outline(&self) -> kurbo::BezPath` (scaled to 1000 units-per-em, supporting TrueType, OpenType, CFF, Type1, and the 14 standard PDF fonts bundled via `hayro-interpret`'s `embed-fonts` feature)
     - `as_unicode(&self) -> Option<BfString>` (resolving via `ToUnicode` CMap → Adobe Glyph List → `uniXXXX`/`uXXXX` glyph names)
     - `font_data(&self) -> Option<OutlineFontData>` (raw font bytes + face index for TrueType/OpenType fonts)
     - `advance_width(&self) -> Option<f32>`
     - `font_cache_key(&self) -> u128`
   - `Glyph::Type3(Box<Type3Glyph<'a>>)` provides:
     - `as_unicode(&self) -> Option<BfString>`
     - `interpret(&self, device, transform, glyph_transform, paint)` to recursively emit the Type3 glyph's drawing operations into the same `Device`.

3. **Empirical Results on Corpus and Round-Trip PDFs:**
   - **`test-files/testComment.pdf`**:
     - Parsed in `hayro-syntax` (`1` page, `612×792 pt`).
     - `hayro-interpret` emitted `8` `GlyphRun`s containing `52` `OutlineGlyph`s (`52/52` with Unicode mappings, `52/52` with raw `OutlineFontData`), `11` vector paths, and `6` clip paths.
     - Extracted text: `"Here is some text. Comment [MM1]: Here is a comment "` (matching the clean baseline-aware extraction without the `"H \nere is some"` split).
     - `hayro::render` rasterized page 0 to a `612×792` RGBA pixmap cleanly.
   - **`krilla 0.8.2` → `hayro-interpret 0.8.0` round-trip**:
     - `hayro-interpret` extracted all `83` subsetted `OutlineGlyph`s and their exact Unicode text via the `/ToUnicode` CMap generated by `krilla`.

4. **Licensing & Safety:**
   - `hayro`, `hayro-interpret`, `hayro-syntax`, `hayro-cmap`, `hayro-postscript`, `hayro-ccitt`, `hayro-jbig2`, and `hayro-jpeg2000` are all dual-licensed `Apache-2.0 OR MIT` and pass `cargo deny check`.
   - `hayro` and `hayro-interpret` enforce `#![forbid(unsafe_code)]`.

## Decision

1. **Primary path — Interpret PDF pages into `LayoutPage` via `hayro-interpret`:**
   - Implement a custom `hayro_interpret::Device` (`PdfLayoutDevice`) that populates `LayoutPage`:
     - Apply `page.initial_transform(true)` so PDF user space (bottom-left origin, `+y` up, plus page `/Rotate` and `/CropBox`) is transformed into `prism-layout`'s top-left origin (`+y` down) coordinate space.
     - Convert `GlyphRun`s into `Item::Glyphs`:
       - Register `OutlineGlyph::font_data()` in `LayoutDocument::fonts` (`FontStore`), keyed by `font_cache_key()`.
       - For Type1 fonts where `font_data()` is `None`, cache the `1000`-upem `OutlineGlyph::outline()` in `FontStore` so SVG `<defs>`, `tiny-skia` rasterization, and `krilla` PDF export can render exact glyph outlines while preserving `GlyphRun::text` and `clusters` for text extraction, selection, and search.
       - For `Glyph::Type3`, invoke `t3.interpret(self, ...)` for visual paths/images and emit an invisible `GlyphRun` carrying `t3.as_unicode()` so Type3 text remains selectable and searchable.
     - Convert `draw_path` / `draw_rect` into `Item::Path` (resolving solid colors, linear/radial gradients, and stroke styles).
     - Convert `draw_image` into `Item::Image` (enforcing `LayoutOptions::max_image_pixels` and `max_decompressed_bytes`).
     - Convert `push_clip_path` / `push_transparency_group` into `Item::Group` (enforcing `LayoutOptions::max_recursion_depth`).
2. **Text extraction & metadata:**
   - Replace `lopdf` content-stream text extraction in `PdfParser` with `LayoutPage::text()` derived from the `hayro-interpret` pass (falling back to `lopdf` content-stream extraction only if `hayro_syntax::Pdf::new` fails on a severely damaged xref table that `lopdf` can still partially read).
   - Keep `lopdf` for `/Info` dictionary metadata (title, author, creation/modification dates) and document bookmarks/outlines.
3. **Graceful degradation & two-tier fallback:**
   - **Encrypted PDFs:** Try empty password first (`hayro-syntax` / `lopdf`). If user-password encrypted and unreadable, return a deterministic `Error::PasswordRequired` (or degraded metadata-only document when requested) without panicking.
   - **Per-page raster fallback:** If a page uses advanced PDF shading/pattern constructs (e.g., Coons/tensor-product mesh shadings) that `PdfLayoutDevice` cannot represent losslessly as `Item::Path`, fall back for that page (or shading item) to `hayro::render` into an `Item::Image` while still emitting the page's `Item::Glyphs` on top so text remains 100% selectable and searchable.
   - **Per-document viewer fallback:** Keep the Phase 0 bundled `pdf.js` path (`EmbeddedKind::Pdf`) available behind a render option and as an automatic fallback if a damaged PDF fails both `hayro-syntax` and `lopdf` page interpretation.

## Consequences

- **Positive:** PDFs become first-class citizens of `LayoutDocument`—unified text extraction, character boxes, search hits, SVG rendering, PNG/TIFF export, and PDF re-export all work identically to PPTX and DOCX without any C/C++ library (`pdfium`/`mupdf`) or headless browser.
- **Negative / Trade-offs:** `hayro-interpret 0.8.0` requires Rust `1.92+` (the workspace toolchain is `rustc 1.99.1`), so workspace `rust-version` metadata should reflect `1.92` when `hayro-interpret` is added in M4.
